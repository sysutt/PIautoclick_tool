# C63 螺旋星云(NGC7293)完整配方 —— 用户手把手 19 步(2026-08-04 验证)

行星状星云 + 窄带(Ha/OIII/SII)+ RGB。**RGB 只用来出星点**(用户纠正:RGB 的星云部分对最终效果帮助不大)。
关键特色:①中心 Ha 里的**类星点真实结构(彗状结节)**必须用**星点蒙版**保护;②每通道**手工分级拉伸 + 蒙版内提亮暗弱信号 + 反复降噪**;③H/O 用动态 HOO 公式合成,SII 只作为**黄色特征的蒙版层**叠加。

## 前置(程序侧已自动化)
六通道 master:整合(**剔除须真生效**,见 wbpp-stacking 铁律)→ **统一裁黑边** → **裁后 GC** → BXT → 线性。

## 1) 复查梯度
STF 拉伸看一眼:若仍有**轻微梯度** → **再跑一次 GC**(GradientCorrection)。别跳过这步复查。

## 2) RGB → 星点
合成 RGB → **天文解析 + SPCC 校色** → **HT 拉伸** → 提取星点(SXT)。RGB 星云弃用。

## 3) 星点蒙版保护 Ha 的彗状结节(**本目标最关键**)
从 RGB 星点图**提取 L 通道** → **大幅提亮** → 作为**蒙版挂在 Ha 上** → 再对 Ha 跑 SXT。
这样**只在真实恒星位置去星**,中心那些"看起来像星点"的**彗状结节**得以保留。
(原理:恒星在宽带 RGB 必然明亮;结节是窄带 Ha 发射,RGB 里几乎没有。)

## 4~8) Ha 通道
4. **HT 初步拉伸**(实测参数:`Shadows 0.0759`、`Midtones 0.2740`、`Highlights 1.0`)。
5. **NXT 降噪 ≈0.6**。
6. **RangeSelection 建亮度蒙版**覆盖**星云核心**:`Lower 0.35`、`Upper 1.0`、`Fuzziness 0`、
   **`Smoothness 60.5`**、勾 **Lightness**。
7. 蒙版应用到 H → **翻转蒙版** → **CT(CurvesTransformation)提亮暗弱 Ha**
   (实测控制点:输入 **0.18346** → 输出 **0.26357**,S 形上抬)。
8. **保持蒙版开启** → NXT 再降噪 ≈0.6 → 关蒙版。H 完成。

## 9~11) SII 通道
9. **不需要星点蒙版**,常规 SXT 去星 + HT 拉伸;拉完**先看整体亮度与噪声**。
10. SII 拉伸后**信号偏弱** → 先 NXT 降噪一次 → **CT 手动拉伸**:第一控制点仍在
    **12145/65535 ≈ 0.185**,第二控制点**大幅提亮**;这样的提亮**做两次**直到亮度到位
    (实测某次控制点:输入 **0.14212** → 输出 **0.19638**)。
11. 此时噪点更明显 → **NXT 两次**:先 **0.7**,再 **0.5**。SII 完成。

## 12~15) OIII 通道
12. HT 拉伸后 → **NXT 0.6**;若觉得锐度不足 → **BXT 锐化 0.5**。
13. **CT 拉伸**(实测控制点:输入 **0.19897** → 输出 **0.27649**)。
14. 边缘 OIII 还有余量 → **RangeSelection 建亮度蒙版覆盖 OIII 椭圆主体** → 应用到 OIII →
    **翻转蒙版** → **CT 再提亮边缘 OIII**。
15. **保持蒙版** → 对提亮部分降噪。OIII 完成。

## 16~19) 合成与调色
16. 用**动态 HOO 公式**先合成 H 与 O(`~x=1-x`,`^` 为幂):
    - `R = 0.8*H`
    - `G = ((O*H)^~(O*H))*H + ~((O*H)^~(O*H))*O`
    - `B = ~((~O)*(~(~H*O)))`
17. 合成后**背景偏蓝是正常的** → 用 **CT 手动调背景色彩平衡**,把背景压成**中性灰**;
    背景中性后星云主体的颜色也就顺眼了。
18. 把 **SII 图层以蒙版形式叠加**到上一步的合成图上,**提升 R、G 通道的饱和度与亮度**,
    让**星云内圈 SII 信号的位置呈现黄色**特征。(用户提示:**这一步用 PixelMath 计算更可控**。)
19. 末尾微调:**提星云饱和**、**增强核心蓝**;**外围 Ha 区域降一点绿、加一点红**;
    最后**合回星点**。

# 第二部分:合成后的精细调色(用户手把手,2026-08-05 验证)

起点 = HOO 合成图,**主体偏黄是正常的**(Ha 比 OIII 强)。以下每步都是"先量数值 → 再定曲线"。

## C1) 背景归中性灰(**最重要的一步,先做**)
先在背景处**读出 R/G/B 三个值**(`lumprobe` → `bgColor`;实测 R 0.084 / G 0.114 / B 0.205 = 偏蓝)。
目标:**三个值各自都到 ≈0.10**。做法 = **逐通道 CT**(`curves` 的 `pointsR/pointsG/pointsB`):
- 每条曲线在**它自己的背景电平**处放一个点,拉到共同目标 0.10;
- 背景上方留一段缓坡(实测形状:输入 +0.06 → 输出 +0.055,来自用户 B 通道 0.19380→0.25065 / 0.10→0.15);
- **在 0.65 处放一个"输出=输入"的锚点钉住高光** —— 否则压蓝会连带把星云亮部的蓝色一起削掉。
- 偏得最多的通道点最多(用户 B 通道用了三个点),G 通常不用动。
验证:再读一次 `bgColor`,三值互差应 <0.01(实测 0.0996/0.1000/0.1002)。
> 与 `bgneutral`(四角加性偏移)的区别:逐通道曲线**只动背景电平附近**,亮部被锚点钉住 → 更精准。

## C2) SII 当**蒙版**叠加,把内圈染黄
把 SII(单通道非线性图)直接作为 `params.mask` 挂上,再跑 CT:
- **在背景电平处放锚点(输出=输入)** —— 关键:SII 图背景残值 ≈0.107,蒙版会把 10% 的效果漏到背景,
  但曲线在背景处是恒等的,所以漏了也无害。
- 右侧抬 **R、G 和 K(亮度)**(实测 0.35→0.46 / 0.35→0.44 / 0.35→0.42),`saturation +0.08`。
→ 只有 SII 强的**内圈**变黄,背景不动。

## C3) 蓝色**色度蒙版** → 核心去黄增蓝
用 `huemask`(hue=blue / mode=chrominance / width=0.10 / blurSigma=15 / blurTimes=2 —— 等价于手动
`ColorMask` 脚本 `E1=0(色度) E2=1.0(强度)` + `gconv($T,15,1,0)` 做两次)得到蒙版,挂上后 CT:
**降 R、提 B、加对比**(饱和度不必另加,色比一改本身就提饱和)。
**跨图移植目标色的正确姿势(踩过两个坑)**:
- 移植**目标色的 RGB 占比 + 亮度变化率**,**不要**移植逐通道增益。用户实测
  `0.5138/0.5692/0.7266 → 0.4196/0.5269/0.9719` → 占比 `(0.2189, 0.2749, 0.5070)`、亮度 ×1.060。
  按占比反解本图目标:`s=(R+G+B)·1.06`,`目标=占比×s`。
  (直接照搬 ×0.817/×0.926/×1.337 → 起点色比不同,核心被推成**死板纯蓝块**。)
- 取样必须用 **`hueStats.blueCore`(p98)**,不能用 `blue`(p90) —— p90 把整片淡蓝晕算进来,
  曲线的陡段落在错误电平上。

## C4) 红色蒙版 → 外围 Ha 加红降绿(可选)
`huemask hue=red` → 挂上 → CT:R ×1.08、**G ×0.94**(用户:外围 Ha"降一点绿、加一点红")。

## C5) 合星
星点偏绿:**牛反拍的星点常规不做去绿**;只有偏绿明显才做一次轻 SCNR。
判据必须用 **`colorPct=0.999`** 取样星核(实测 greenFrac 0.357 → 不做;若用默认 p90 会量到 0.409 而误判)。

## 这一轮修掉的三个上游错误(比调色本身更值钱)
1. **全图降噪毁结构** → 见铁律 20。OIII/SII 改成"背景蒙版重降噪 + 主体轻降噪 + lhe 找回层次"后,
   空腔的丝状结构、内圈纹理才回来。
2. **Ha 双重拉伸** → 见铁律 21。自适应 `stretch` 之后又套 `htstretch(midtones 0.2740)`,
   Ha 变成 faint 0.742 / core 0.859(动态范围仅 0.117)= 环带死白,还压掉合成里 OIII 的蓝色层次。
   改成**单次 stretch + 保斜率抬升曲线**(faint 0.627 / core 0.800,范围 0.173)。
3. **改了通道电平却没改合成增益** → 见铁律 22。Ha 变温和后 `hGain=0.8` 让 R 成最弱通道 → 环带发紫;
   `hGain=1.0` 才回暖。
4. `starsep` 的 `params.mask` **无效**(SXT 不认视图蒙版)→ 保结节必须"全图去星 → `maskblend`
   把非星点位置换回原图"。见 [[pi-c63-knots-starmask]]。

## 与自动流程的差异(要点)
- **RGB 只出星点**:这份数据 RGB 星云信号对成片无帮助 → 不做 RGB 星云融合。
- **逐通道手工分级**:不是一把拉伸,而是"HT 粗拉 → 降噪 → 蒙版内提暗弱 → 再降噪",每通道按信号强弱不同处理次数(SII 最弱、提亮两次 + 降噪两次)。
- **蒙版套路统一**:`RangeSelection` 建**覆盖主体**的亮度蒙版 → 应用 → **翻转** → CT 只提亮**主体之外的暗弱信号** → 保持蒙版降噪。这招在 H 与 OIII 上都用。
- SII 不进 SHO 三色映射,而是**作为黄色特征的调色层**。
