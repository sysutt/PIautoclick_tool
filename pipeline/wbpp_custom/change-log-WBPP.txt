2026/03/30 - v3.0.1
-------------------------------------------------------------------------------

- Bugfix: The order of output pedestal mode combo box items was reversed with
  respect to the constants defined by the ImageCalibration process (Literal
  must be first, Auto must be second).

- Bugfix: file paths containing non-ASCII characters (e.g., degree symbol)
  in saved groups were corrupted on reload due to Latin-1/UTF-8 encoding
  mismatch in ByteArray serialization.

- Removed redundant enumerations in BPP-Global.js. Some process constants were
  being redefined by JavaScript objects.

- Corrected improper usage of the word "epoch" in our astrometry engine and
  auxiliary classes.

2026/03/26 - v3.0.0
-------------------------------------------------------------------------------

- Migration to the V8 JavaScript engine. The #engine v8 directive is now used
  in place of the legacy SpiderMonkey runtime. PixInsight core version >= 1.9.4
  is required.

- Improvement: general revision of tooltips, console messages, and inline
  documentation across the entire codebase for clarity and consistency.

- Minor bugfixes.

  formats.

  warning and error messages.

  all group functions available for a frame group object.

  enabled then the file name was duplicated into the masters after
  the astrometric solution step.

- Bugfix: The Autocrop step was appearing in the pipeline also when no master
  light generation was planned.

2024/08/10 - v2.7.6
-------------------------------------------------------------------------------

- Improvement: The check of the maximum life time of the cache entries has been
  removed when WBPP is launched.

- Improvement: Missing noise and signal warnings generated by Subframe Selector
  are now suppressed.

- Improvement: When the custom formula is selected as the weighting method and
  integration is enabled, the light frames weights are hold in memory and
  provided to Image Integration as a csv weights file. As a consequence,
  the WBPPWGHT fits keyword is no more stored into the registered light frames.
  This significantly improves the execution speed when using that weighting
  method and allows to efficiently compare the usage of different weighting
  methods.

- Bugfix: When the custom formula weights were changing, several steps were
  entirely re-executed instead of relying to the cached files from the previous
  excecution.

- Bugfix: Fixed wrong tool tip for the 'High sigma' control. Replaced
  'increase' by 'decrease' because the lower the high sigma value, the more hot
  pixels can be selected by the automatic cosmetic correction feature.
